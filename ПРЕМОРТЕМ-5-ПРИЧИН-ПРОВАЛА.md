# Премортем: 5 причин, почему проект КФХ Кенеш может провалиться

> Составлено на основе опыта BossYoki и анализа текущего кода.

---

## 1. localStorage = данные живут только в одном браузере

**Что произойдёт:** Покупатель сделал заказ → он видит его в своём браузере. Продавец opening админку на другом телефоне → пусто. Заказ потерян.

**Почему это критично:** Это ГЛАВНАЯ проблема проекта прямо сейчас. В `App.tsx` всё хранится в `localStorage` — нет синхронизации. Один браузер = одна копия данных.

**Как минимизировать:**
- **Фаза 2 плана (Telegram-бот)** — заказы уходят напрямую продавцу, минуя localStorage
- До Фазы 2: предупредить продавца, что админка работает ТОЛЬКО в том браузере, где он её открыл
- Не хранить критичные данные только в localStorage

**Триггер-индикатор:** Продавец говорит «я не вижу заказов».

## 2. Картинки не инлайнены в singlefile — 404 при деплое

**Что произойдёт:** `npm run build` собирает один `index.html`, но картинки из `public/images/` копируются отдельно в `dist/images/`. Если закинуть только `index.html` на хостинг без папки `images/` — все картинки сломаются.

**Почему это критично:** В `vite.config.ts` используется `viteSingleFile()`, но он инлайнит JS/CSS, а НЕ картинки. В `dist/` уже лежит папка `images/` — значит они не встроены.

**Как минимизировать:**
- При деплое на Vercel/GitHub Pages копировать ВСЮ папку `dist/`, а не только `index.html`
- Проверить после деплоа: открыть сайт на телефоне, убедиться что картинки грузятся
- Рассмотреть `vite-plugin-assets` для инлайна картинок (но это увеличит размер HTML)

**Триггер-индикатор:** Серые квадраты вместо фото на сайте.

## 3. Токен Telegram-бота будет в клиентском коде

**Что произойдёт:** В Фазе 2 добавляем `fetch` на `https://api.telegram.org/bot<TOKEN>/sendMessage`. Токен окажется в JavaScript, который видит каждый покупатель через DevTools.

**Почему это критично:** Любой сможет достать токен и слать сообщения от имени бота. Для фермерского сайта это не катастрофа (максимум — спам в чат продавца), но нарушение безопасности.

**Как минимизировать:**
- Использовать **одноразовый токен** бота (не основной рабочий)
- Ограничить бота: настроить команды только на отправку, не на чтение
- Позже: проксировать через Cloudflare Worker (бесплатно)
- Или: кнопки «Заказать в WhatsApp/Telegram» (Фаза 3) — безопаснее, токен не нужен

**Триггер-индикатор:** Спам-сообщения в чате продавца.

## 4. Контакты-заглушки: номер не существует

**Что произойдёт:** На сайте указан `+7 (900) 123-45-67` и `info@kenesh-farm.ru`. Если покупатель позвонит — номер не существует или принадлежит другому человеку.

**Почему это критично:** Это УЖЕ в коде (`App.tsx` и `CLAUDE.md`). В ДЕПЛОЙ-ПЛАНЕ написано «заменить в Фазе 5», но сайт уже может быть задеплоен с заглушками. Потерянные клиенты = потерянные деньги.

**Как минимизировать:**
- **СЕЙЧАС:** убедиться, что реальные контакты вбиты в код перед деплоем
- Проверить номер телефона фермы
- Не деплоить с заглушками — это приоритет выше PWA и аналитики

**Триггер-индикатор:** Покупатель говорит «номер не работает».

## 5. Render-привычка: забыть про Vercel и деплоить по-старому

**Что произойдёт:** Привычка из BossYoki: « Manual Deploy → Clear build cache ». На Vercel такого нет — деплой автоматический при каждом `git push`. Но если забыть запушить — сайт не обновится.

**Почему это критично:** Из опыта BossYoki:
- Render не подхватывает код автоматически → нужен Manual Deploy
- Vercel делает наоборот — АВТОМАТИЧЕСКИ при коммите
- Нужно перестроить мышление: «запушил = задеплоилось»

**Как минимизировать:**
- После `git push` проверять Vercel Dashboard — появился ли новый деплой
- Не бояться: Vercel не засыпает, не требует ручного деплоя
- Настроить уведомления в Telegram/Email о деплое (в настройках Vercel)

**Триггер-индикатор:** Сайт не обновился после правок.
